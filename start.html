BEGINNER TO KERNEL DEVELOPER

Build your first operating system

Follow these stages in order. The goal of your first project is not to recreate Windows or Linux immediately. It is to boot a small kernel, understand how it works, and gradually add capabilities.

Important: Use a virtual machine for early experiments. Never overwrite your normal computer's bootloader or test experimental kernels on important data.

Stage 1 — Decide what you are building

Choose your kernel approach

Linux-based: Start with the Linux kernel and add a root filesystem, utilities, and optionally a desktop.

From scratch: Write your own kernel in C or Rust, with assembly where needed. This teaches more low-level fundamentals but requires substantially more work.

Select your target

For a first hobby kernel, x86_64 is a common target. Record the architecture, firmware type (UEFI or BIOS), compiler, and emulator before choosing build instructions.

Stage 2 — Install your development tools

For a from-scratch C/assembly kernel, you typically need:

  • Git for source control.
  • An assembler such as NASM, if your boot path uses NASM.
  • A suitable compiler and linker, preferably a target-aware cross-toolchain for a freestanding kernel.
  • Make or another build system.
  • QEMU for virtual machine testing.
  • A debugger such as GDB for investigating crashes.

On Windows, WSL2 with a Linux development environment is often a convenient route for following Unix-oriented OS development tutorials. Native Windows toolchains are possible, but their commands and paths may differ.

Stage 3 — Create your project

Make a project directory with this structure:

MyOS/
├── boot/
├── kernel/
├── include/
├── linker/
├── build/
├── Makefile
└── README.md

Keep source files separate from generated output. The exact files depend on whether you use an existing boot protocol, a custom EFI loader, or a Linux-based build system.

Stage 4 — Define how the kernel starts

The bootloader and kernel must agree on the entry point and any information passed at startup. That information may include the memory map, framebuffer, firmware tables, and boot options.

For a modern UEFI project, you can write an EFI loader that loads a kernel image. Alternatively, use a documented existing boot protocol to reduce the amount of bootloader code you must write.

Stage 5 — Compile and link

Use a linker script or the linker configuration appropriate for your kernel format. Check the output architecture, entry point, and section addresses. A compiler reporting success does not guarantee that the result is bootable.

Keep a record of the compiler version, target triple, linker options, source revision, and build command so you can reproduce the build.

Stage 6 — Boot in a virtual machine

Start with a small, verifiable milestone: boot successfully and print a message through serial output or a framebuffer. Inspect emulator logs and use a debugger if the kernel stops unexpectedly.

Stage 7 — Expand the kernel

CPU exceptions

Handle faults and record diagnostic information.

Memory management

Introduce physical allocation and virtual memory.

Interrupts and timers

Handle hardware events and measure elapsed time.

Scheduling

Move from one execution path toward multiple tasks.

Drivers and storage

Add hardware support and a filesystem.

User space

Introduce system calls, programs, and a shell.
