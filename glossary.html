Operating system glossary

Learn the terminology you'll encounter while building an OS.

Kernel

The privileged core responsible for managing memory, CPU execution, hardware access, and system calls.

Bootloader

Software that prepares the machine and loads or starts the kernel.

UEFI

A modern firmware interface that can launch EFI applications and provide boot-time services.

EFI application

A firmware-compatible executable, usually in PE/COFF format, that UEFI can load.

Cross-compiler

A compiler that runs on one system while generating code for a different target architecture or platform.

Linker script

A file describing how code and data sections are arranged in the linked output.

Interrupt

An event that redirects execution to a handler, often to respond to hardware or processor events.

Virtual memory

A mechanism that maps virtual addresses to physical memory and can isolate the address spaces of different processes.

Root filesystem

The initial filesystem containing the programs, libraries, and configuration needed by a Linux system.

Init system

The first user-space process, which initializes services and coordinates system startup.

QEMU

A machine emulator and virtualizer commonly used to test kernels without booting them on the host computer.

ELF

A common executable and object-file format used by many Unix-like systems. UEFI applications normally use PE/COFF instead.

System call

A controlled interface through which a user-space program requests a service from the kernel.

Scheduler

The kernel component that determines which runnable task gets CPU time.

Driver

Software that allows the operating system to interact with a particular hardware device or interface.

Development tip: Record your toolchain version, target architecture, source revision, configuration, and build command. This makes it easier to reproduce a working build and diagnose regressions.
