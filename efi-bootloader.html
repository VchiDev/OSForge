OSFORGE DEVELOPMENT LAB

UEFI & BIOS Bootloader Lab

Learn how to build a UEFI application and a legacy BIOS boot sector using Ubuntu, Debian, Windows Subsystem for Linux (WSL), Visual Studio Code, and QEMU.

UEFI tutorial BIOS tutorial Troubleshooting
What you'll build: a UEFI application named BOOTX64.EFI and a 512-byte BIOS boot sector named boot.bin. These are introductory boot demonstrations, not complete operating-system loaders.

1. Set up your development environment

You can follow this lab on Ubuntu, Debian, or Ubuntu running under WSL on Windows.

Install the development tools

Run these commands in the Ubuntu or Debian terminal:

sudo apt update
sudo apt install build-essential binutils nasm git make 
  qemu-system-x86 ovmf gnu-efi mtools dosfstools

Using WSL on Windows

Open Windows PowerShell and install Ubuntu if necessary:

wsl --install Ubuntu

Restart Windows if requested, open Ubuntu, and complete its initial setup.

Install Visual Studio Code on Windows, then install Microsoft's WSL extension. In the Ubuntu terminal, you can open the current Linux directory in VS Code with:

code .
Important: Run Linux build commands in the Ubuntu/Debian terminal, not directly in PowerShell. Keep your project inside the Linux filesystem, such as /home/your-user/osforge-bootlab.

2. UEFI bootloader tutorial

UEFI applications run under UEFI firmware. On x86-64 systems, removable-media boot commonly looks for EFI/BOOT/BOOTX64.EFI on a FAT-formatted partition.

Step 1 — Create the project directory

Copy and run this complete command block:

mkdir -p ~/osforge-bootlab/uefi
cd ~/osforge-bootlab/uefi
pwd

The printed path should end in osforge-bootlab/uefi. Every UEFI source file in this lab must be created in this directory.

Step 2 — Create main.c

Use the following command to create the source file directly in the correct folder. Copy the whole block, including both lines containing EOF:

cat > main.c <<'EOF'
#include <efi.h>
#include <efilib.h>

EFI_STATUS EFIAPI efi_main(
    EFI_HANDLE image_handle,
    EFI_SYSTEM_TABLE *system_table
) {
    InitializeLib(image_handle, system_table);

    Print(L"OSForge UEFI Bootloader Lab\r\n");
    Print(L"UEFI application started successfully.\r\n");
    Print(L"Next step: load a kernel image.\r\n");

    return EFI_SUCCESS;
}
EOF

Verify that the file exists:

ls -l main.c

Step 3 — Locate the GNU-EFI files

Find the startup object, linker script, and libraries installed by your distribution:

dpkg -L gnu-efi | grep -E \
'crt0-efi-x86_64.o|elf_x86_64_efi.lds|libefi.a|libgnuefi.a'

If no files are listed, try reinstalling the package:

sudo apt update
sudo apt install --reinstall gnu-efi

Step 4 — Create the Makefile

This step fixes the common “no makefile found” error. The filename must be exactly Makefile, with a capital M and no .txt extension. Run this command while inside ~/osforge-bootlab/uefi. 
cat > Makefile <<'EOF'
CC = gcc
LD = ld
OBJCOPY = objcopy

EFI_INC = /usr/include/efi
EFI_ARCH_INC = /usr/include/efi/x86_64

EFI_CRT = $(shell dpkg -L gnu-efi | grep '/crt0-efi-x86_64.o$$' | head -n 1)
EFI_LDS = $(shell dpkg -L gnu-efi | grep '/elf_x86_64_efi.lds$$' | head -n 1)
EFI_LIBDIR = $(shell dirname "$$(dpkg -L gnu-efi | grep '/libefi.a$$' | head -n 1)")

CFLAGS = -I$(EFI_INC) -I$(EFI_ARCH_INC) 
         -fpic -ffreestanding -fno-stack-protector 
         -fno-stack-check -fshort-wchar -mno-red-zone 
         -maccumulate-outgoing-args

.PHONY: all clean check

all: check BOOTX64.EFI

check:
	@test -f "$(EFI_CRT)" || (echo "ERROR: GNU-EFI startup object not found."; exit 1)
	@test -f "$(EFI_LDS)" || (echo "ERROR: GNU-EFI linker script not found."; exit 1)
	@test -f "$(EFI_LIBDIR)/libefi.a" || (echo "ERROR: libefi.a not found."; exit 1)
	@test -f "$(EFI_LIBDIR)/libgnuefi.a" || (echo "ERROR: libgnuefi.a not found."; exit 1)
	@test -f main.c || (echo "ERROR: main.c is missing."; exit 1)

main.o: main.c
	$(CC) $(CFLAGS) -c main.c -o main.o

boot.so: main.o
	$(LD) -nostdlib -znocombreloc 
	    -T "$(EFI_LDS)" -shared -Bsymbolic 
	    "$(EFI_CRT)" main.o 
	    -L"$(EFI_LIBDIR)" -lefi -lgnuefi -o boot.so

BOOTX64.EFI: boot.so
	$(OBJCOPY) 
	    -j .text -j .sdata -j .data -j .dynamic 
	    -j .dynsym -j .rel -j .rela -j .reloc 
	    --target=efi-app-x86_64 boot.so BOOTX64.EFI

clean:
	rm -f main.o boot.so BOOTX64.EFI
EOF

Note: The recipe lines in a Makefile must begin with actual tab characters. The command above writes the tabs automatically. Do not type the word EOF into the Makefile itself; it marks the end of the input command.

Step 5 — Verify and build

First, confirm that both source files exist in the current directory:

cd ~/osforge-bootlab/uefi
ls -la

You should see main.c and Makefile.

Ask Make to preview the build commands:

make -n

Then build the application:

make clean
make

If successful, verify the output:

ls -l BOOTX64.EFI
file BOOTX64.EFI
Expected result: a file named BOOTX64.EFI. If Step 5 fails, use the troubleshooting guide below before proceeding.

Step 6 — Create a FAT disk image

Run these commands from the same UEFI project directory:

mkdir -p esp/EFI/BOOT
cp BOOTX64.EFI esp/EFI/BOOT/BOOTX64.EFI

dd if=/dev/zero of=uefi.img bs=1M count=64
mkfs.fat -F 32 uefi.img
mcopy -i uefi.img -s esp/EFI ::/

This creates a 64 MB FAT image containing the UEFI application at the standard x86-64 removable-media path.

Step 7 — Find UEFI firmware for QEMU

Find the OVMF firmware files installed by your Linux distribution:

find /usr/share/OVMF /usr/share/ovmf \
  -type f 2>/dev/null

Locate the x86-64 firmware code image, commonly named OVMF_CODE.fd. Some installations also provide a variable-store template, commonly named OVMF_VARS.fd.

If a variable-store template is available, copy it into your project directory:

cp /PATH/TO/OVMF_VARS.fd ./OVMF_VARS.fd

Replace the example path with the real path on your machine. Start QEMU with the real firmware paths:

qemu-system-x86_64 
  -machine q35 
  -m 512 
  -drive if=pflash,format=raw,readonly=on,file=/PATH/TO/OVMF_CODE.fd 
  -drive if=pflash,format=raw,file=OVMF_VARS.fd 
  -drive format=raw,file=uefi.img

Replace /PATH/TO/OVMF_CODE.fd with the actual firmware code path. If your distribution packages OVMF differently, consult its package documentation. Graphical QEMU may require a Linux desktop or a supported display configuration when using WSL.

Step 8 — Next steps

Once your application runs, develop the actual loader in stages:

  1. Locate and validate a kernel image.
  2. Load the kernel into suitable memory.
  3. Collect memory-map information and define a kernel handoff structure.
  4. Call ExitBootServices correctly before taking over memory management.
  5. Transfer control to the kernel's entry point using a documented calling convention.

These steps require a defined kernel format and careful memory management. The initial message-printing application is not yet a full OS bootloader.

3. Legacy BIOS bootloader tutorial

The traditional BIOS boot process differs from UEFI. For this lab, NASM creates a 512-byte boot sector that prints a message using BIOS video services.

Step 1 — Create the BIOS project directory

mkdir -p ~/osforge-bootlab/bios
cd ~/osforge-bootlab/bios

Step 2 — Create boot.asm

cat > boot.asm <<'EOF'
bits 16
org 0x7C00

start:
    xor ax, ax
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov sp, 0x7C00

    mov si, message

print_character:
    lodsb
    test al, al
    jz finished

    mov ah, 0x0E
    int 0x10
    jmp print_character

finished:
    cli

halt:
    hlt
    jmp halt

message db 'OSForge BIOS Bootloader!', 13, 10
        db 'The boot sector is running.', 0

times 510 - ($ - $$) db 0
dw 0xAA55
EOF

Step 3 — Assemble it

nasm -f bin boot.asm -o boot.bin
wc -c boot.bin

The expected size is exactly 512 bytes.

Step 4 — Boot in QEMU

qemu-system-i386 \
  -drive file=boot.bin,format=raw,if=floppy

The virtual machine should display the OSForge BIOS message and then halt. This is a bootable demonstration sector, not a complete kernel loader. A full BIOS loader needs additional code to read more sectors and prepare the kernel's execution environment.

QEMU or VirtualBox? QEMU is convenient for rapid bootloader testing. VirtualBox can also be used, but the virtual machine's firmware mode must match the lab: enable EFI for UEFI testing and disable EFI for legacy BIOS testing where supported.

4. Troubleshooting

Error: No rule to make target 'clean'

Make found a Makefile, but it did not contain the requested clean rule. You may be using the wrong file or an incomplete Makefile. Return to the UEFI project directory and inspect the files:

cd ~/osforge-bootlab/uefi
pwd
ls -la
cat Makefile

If the Makefile is missing or its contents are incorrect, repeat UEFI Step 4.

Error: No targets specified and no makefile found

This usually means you ran make from the wrong directory or did not create the Makefile. Run:

cd ~/osforge-bootlab/uefi
ls -la
make

Check that Makefile is listed. If the file was accidentally saved as Makefile.txt, rename it:

mv Makefile.txt Makefile

Error: No rule to make target 'main.c'

The Makefile cannot find the C source file in the project directory. Repeat UEFI Step 2 and confirm the file exists with ls -l main.c.

Error: missing separator

Makefile command lines must begin with a literal tab. Repeat UEFI Step 4 using the terminal command, which preserves the required tabs.

GNU-EFI libraries or linker script not found

Inspect the installed paths:

dpkg -L gnu-efi | grep -E \
'crt0-efi-x86_64.o|elf_x86_64_efi.lds|libefi.a|libgnuefi.a'

If the Makefile's checks fail, the package paths or installed files differ from the expected layout. Use the displayed paths to adjust the Makefile for your distribution.

Compiler or assembler command not found

sudo apt update
sudo apt install build-essential binutils nasm make gnu-efi

EFI target is not supported by objcopy

Check the available targets:

objcopy --info | grep -i efi

If the expected target is unavailable, your binutils package or EFI conversion process needs to be adjusted.

QEMU cannot find firmware

ls -l uefi.img
find /usr/share/OVMF /usr/share/ovmf -type f 2>/dev/null

Use the actual firmware paths reported by your system rather than the example paths in Step 7.

5. Completion checklist

  • Ubuntu, Debian, or WSL has the required build tools.
  • main.c and Makefile are in the UEFI project directory.
  • make creates BOOTX64.EFI.
  • The FAT image contains EFI/BOOT/BOOTX64.EFI.
  • The UEFI application is tested with QEMU and OVMF.
  • The BIOS example assembles to exactly 512 bytes.
  • The BIOS example boots in QEMU.
