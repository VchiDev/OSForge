UEFI DEVELOPMENT LAB

Create your own .efi bootloader

A custom EFI application can display a boot menu, read configuration, locate a kernel, collect firmware information, and transfer control to your operating system.

Test with a virtual machine and a disposable EFI System Partition. Do not replace your computer's working boot files while learning.

Step 1 — Understand the boot process

UEFI firmware

The firmware initializes the platform and loads a compatible EFI application from a boot entry or EFI System Partition.

Your EFI loader

The loader can read configuration, locate the kernel, validate its format, and prepare the information required by the kernel.

Kernel handoff

The loader transfers control using a defined entry point and documented boot information structure. The kernel then initializes its own execution environment.

Step 2 — Select a development language

C

Use a UEFI-compatible C toolchain and headers. EDK II is a widely used framework for developing UEFI applications and drivers.

EDK II source →

Rust

Use a supported UEFI target and compatible UEFI libraries. Follow the selected project's build instructions and confirm that its output is a firmware-compatible EFI application.

Step 3 — Define the loader-to-kernel interface

Before writing the loader, document:

  • Kernel executable format and architecture.
  • Kernel entry point and calling convention.
  • Memory-map representation and reserved regions.
  • Framebuffer details, if graphics are needed.
  • Firmware tables and boot options passed to the kernel.
  • When and how UEFI boot services are exited.

Step 4 — Build a minimal EFI application

  1. Install the toolchain and SDK required by your chosen framework.
  2. Create an EFI application entry point using that framework's template.
  3. Print a message using the provided UEFI console interface.
  4. Compile the application for the firmware's architecture.
  5. Verify the executable format and output file.

For a framework such as EDK II, use its official build system and sample applications rather than assuming a normal desktop executable can be renamed to .efi.

Step 5 — Test in a virtual machine

  1. Install QEMU and obtain a compatible OVMF UEFI firmware image.
  2. Create a disposable FAT-formatted EFI System Partition image.
  3. Place your EFI application in the appropriate test boot path.
  4. Launch QEMU with UEFI firmware and inspect the console output.
  5. Fix errors before adding kernel-loading functionality.

Step 6 — Add kernel loading

After the minimal application works, add file discovery, format validation, memory allocation, configuration parsing, diagnostics, and a documented kernel handoff. Follow the UEFI specification when retrieving the final memory map and exiting boot services.

A valid EFI application is not automatically a bootable operating system. Your loader must be compatible with the firmware, and your kernel must implement the agreed handoff contract.
